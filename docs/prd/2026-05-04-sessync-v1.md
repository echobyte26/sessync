# sessync v1 PRD

> Date: 2026-05-04
> Status: Locked for v1 implementation
> Owner: @jameschen

## 一句话定义

把 Claude Code 的 session 在两台 Mac 之间自动加密同步，切设备无需重述上下文。

## 用户与场景

### 目标用户

单用户（项目作者本人），双 Mac 工作流：
- 设备 A：MacBook Pro（移动）
- 设备 B：Mac mini（桌面）
- 两端都常驻 Claude Code，使用同一份代码仓库（路径可能不同）

### 核心场景

1. **离开 A 设备**：在 A 上结束一轮 Claude Code 对话 → Stop hook 触发 → session 自动加密上传 OSS（秒级）
2. **切到 B 设备**：在 B 上跑 `sessync resume` → 交互式选单：list project → list session → 选定 → 拉取并解密到 B 上的目标 cwd → 直接 `claude --resume <id>` 接着干
3. **频次**：上月统计 6-10 次/月，属于高频自用工具

### 不是给谁用的

- ❌ 多人协作（v1 明确单用户；多人是 v2 假设，未经验证）
- ❌ 跨工具迁移用户（不做 Claude Code ↔ Codex ↔ Cursor 的格式转换）
- ❌ 想在网页/手机查看 session 的用户（v1 只做 CLI + 本机文件落盘）
- ❌ 三台以上设备同步（v1 双向，未验证 N 向冲突）

## 需求清单

### Must Have（不做就废）

- [ ] **M1** Tool adapter 接口 + Claude Code 实装（读写 `~/.claude/projects/<encoded-cwd>/<session-id>.jsonl`）
- [ ] **M2** Storage adapter 接口 + 阿里云 OSS 实装（put/get/list/delete）
- [ ] **M3** age 客户端加密（passphrase → argon2id 派生密钥 → age encrypt/decrypt）
- [ ] **M4** 本地配置：AK/SK + bucket + passphrase（存 `~/.config/sessync/config.toml`，passphrase 走 macOS Keychain）
- [ ] **M5** `sessync push` 短命进程：扫描本地新 session → 加密 → 上传 → 更新本地 manifest
- [ ] **M6** Claude Code Stop hook 集成：hook 脚本 spawn `sessync push`
- [ ] **M7** launchd 周期任务（5 min）：spawn `sessync push --retry-pending`
- [ ] **M8** 本地 pending queue（SQLite）：失败的 session 记录 + 重试次数 + 最后错误
- [ ] **M9** `sessync resume` 交互式选单：列项目 → 列 session（按时间倒序，显示首条 user message 摘要）→ 选定 → 拉取 → 落到当前 cwd（或用户指定路径）→ 输出 `claude --resume <id>` 提示
- [ ] **M10** 跨设备路径映射：上传时记录原 cwd；resume 时按目标 cwd 重写 Claude Code 项目目录名（base64 路径编码）
- [ ] **M11** `sessync status` 命令：最后一次 push 时间、pending 数量、最近失败原因
- [ ] **M12** 失败通知：连续失败 ≥ 3 次走 osascript 弹原生通知
- [ ] **M13** 日志：所有事件落 `~/Library/Logs/sessync/sessync.log`，按天 rotate

### Should Have（做了更好）

- [ ] **S1** `sessync init` 引导式配置（提示输 AK/SK / passphrase / bucket）
- [ ] **S2** `sessync doctor` 自检（OSS 连通性、Keychain 可读、hook 安装、launchd 状态）
- [ ] **S3** push 增量：基于本地 manifest 只传新增/变更 session（按 mtime + size 判断）
- [ ] **S4** resume 时本地缓存命中则跳过下载

### Won't Have（明确不做 + 理由）

- ❌ **常驻 daemon**：A(c) 已定，按需 spawn 短命进程更简单可靠，少一个崩溃源
- ❌ **多用户/团队共享**：v1 是 pure (a)，等开源后看 echo 决定是否做 v2
- ❌ **冲突合并/分叉**：Q4 已确认纯串行，无并发
- ❌ **Codex / Cursor 实装**：只留 SessionAdapter 接口，等 v1.x 看用户呼声
- ❌ **R2 / S3 / MinIO / P2P**：留 StorageAdapter 接口，v1 只做阿里云 OSS
- ❌ **Web UI / 手机端**：纯 CLI
- ❌ **跨工具格式转换**：项目边界一开始就排除

## 用户故事 + 验收标准

### Story 1：Stop hook 自动同步

**Given** 设备 A 上 Claude Code 已配置 sessync Stop hook，OSS 配置正确
**When** 用户在 A 上结束一轮对话（Claude 触发 Stop event）
**Then**
- 5 秒内 spawn `sessync push` 进程
- 该进程读取最新 session jsonl → age 加密 → 上传 OSS 对象 `<bucket>/sessions/<project-hash>/<session-id>.age`
- 上传成功后写本地 manifest 标记已同步
- 进程退出码 0，日志记录 `push ok session=<id> bytes=<n>`

### Story 2：B 设备 resume

**Given** 设备 B 已配置同一 OSS bucket + passphrase；A 已 push 过若干 session
**When** 用户在 B 上 `cd <项目目录>` 后跑 `sessync resume`
**Then**
- 列出 OSS 上所有 project（按最近 session 时间倒序）
- 用户选定 project 后，列出该 project 下所有 session（含时间戳 + 首条 user message 前 60 字摘要）
- 用户选定 session 后，sessync 下载 → 解密 → 按当前 cwd 重写 project 目录名 → 落到 `~/.claude/projects/<encoded-current-cwd>/<session-id>.jsonl`
- 终端打印 `Run: claude --resume <session-id>` 提示
- 用户复制粘贴即可继续对话

### Story 3：失败重试 + 通知

**Given** 网络中断，push 连续失败 3 次
**When** 第 3 次 launchd 周期任务执行 `sessync push --retry-pending`
**Then**
- pending queue 记录 retry_count=3
- osascript 弹 macOS 原生通知："sessync: 3 sessions pending, last error: <msg>"
- 通知点击不做特殊跳转（v1 简化）
- 网络恢复后下次 retry 自动清队列

### Story 4：手动查状态

**Given** 用户怀疑同步出问题
**When** 跑 `sessync status`
**Then** 输出：
```
Last push:    2026-05-04 14:23:11 (2 min ago)
Last pull:    2026-05-04 09:11:02
Pending:      0
Failed (24h): 0
Storage:      oss://<bucket> (reachable)
Hook:         installed
launchd:      loaded
```

## Edge Cases

1. **同名 session ID 在两端被先后写入**
   - 现状：Q4 已确认纯串行，约定不会发生
   - 防御：上传前比对 OSS 已存在对象的 mtime；本地 mtime 旧则跳过 + 警告日志

2. **passphrase 错误 / Keychain 被锁**
   - resume 解密失败 → 不落盘任何明文 → CLI 报错 `decryption failed: check passphrase`
   - push 端 Keychain 不可读 → push 进程退出码 ≠ 0，pending queue 记录原因

3. **两端项目路径不同**（A 在 `~/work/foo`，B 在 `~/Project/foo`）
   - 上传时 manifest 记录原 cwd 字符串
   - resume 时按目标 cwd 计算 Claude Code 项目目录编码（base64 / dash-encoded）
   - 不修改 jsonl 内容里的绝对路径（Claude Code resume 不依赖该字段一致性，需在实装阶段验证；列入风险）

4. **OSS 鉴权过期 / AK 被禁用**
   - push 立即失败 → 进 pending queue → 连续 3 次后弹通知
   - `sessync doctor` 能识别 403 并提示更换 AK

5. **session 文件正在被 Claude Code 写入时被 push 读到**
   - Stop hook 在 Claude 写完后才触发，理论上安全
   - 防御：push 读完后再 stat 一次比对 mtime，不一致则重试一次

6. **本地存储满 / OSS 配额满**
   - push 失败进 pending；status 显示原因
   - 不做自动清理（v1 简化）

## 成功指标

可量化、有时间窗口。**v1 上线后 4 周内观测**：

| 指标 | 目标 | 测量方式 |
|---|---|---|
| 切设备 resume 成功率 | ≥ 95% | log 里 `resume ok / resume fail` 计数 |
| Stop hook → OSS 可见延迟 P95 | ≤ 10 秒 | push log 时间戳 - hook 触发时间戳 |
| 切设备时 pending=0 的比例 | ≥ 90% | 每次 resume 前自动记录 status |
| 因 sessync 导致的"重述上下文"次数 | ≤ 1 次/月 | 主观记录，对比 v0（每月 6-10 次） |
| 进程崩溃 / 数据损坏事件 | 0 次 | 任何一次都视为 P0 |

**核心 north star**：4 周内若"重述上下文次数 ≤ 1 次/月" → v1 成立 → 开始考虑开源 + 收集 v2 echo。

## 已知风险

### R1: Claude Code session 格式向前兼容性

Claude Code 的 jsonl session 格式可能在升级中变化（字段增减、路径编码方式调整）。
**缓解**：Tool adapter 层封装格式细节；CI 里冒烟测试主流 Claude Code 版本；锁版本范围在 README 说明。

### R2: 跨路径 resume 的不可见副作用

Story 2 假设"重写项目目录名 + 不动 jsonl 内容"即可让 Claude Code 正常 resume。如果 jsonl 内嵌的绝对路径影响 Claude 行为（比如 tool call 引用旧路径），resume 体验会退化。
**缓解**：实装第一周做穿透测试（A push → B resume → 真实写代码 30 min），列阻断 bug 列表。

### R3: 阿里云 OSS 单点依赖

bucket 失联或账号被封 → 同步彻底中断。
**缓解**：StorageAdapter 接口预留；本地永远保留原始 jsonl，OSS 只是搬运层；必要时 7 天内可切 S3。

### R4: passphrase 丢失等于数据丢失

age 加密无法找回；Keychain 重装系统会丢。
**缓解**：`sessync init` 强制提示用户把 passphrase 抄到密码管理器；README 显著警告。

### R5: 「v2 多人协作」是未经验证的假设

目前没有任何外部用户提过这个需求，仅基于"开源后可能有人要"的猜测。
**缓解**：v1 上线后明确收集 GitHub issue / star 增长，如果 3 个月内 < 5 个 echo 请求多人功能，v2 直接砍掉。**不要在 v1 里为 v2 提前付任何代码代价**（除了已经设计的 Storage/Tool adapter，那是独立合理的工程抽象）。

### R6: launchd 配置漂移

用户重装系统 / 升级 macOS 后 launchd plist 可能失效，周期兜底失灵。
**缓解**：`sessync doctor` 检查 launchd 状态；hook 触发时也顺手扫一次 pending（双重兜底）。
